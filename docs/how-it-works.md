# How Expanse works on Hyprland

Expanse for Hyprland is a plugin running inside the compositor, so unlike
[Expanse for Mac](https://github.com/invig/expanse/blob/main/docs/how-it-works.md) it can draw
live, scaled windows itself and own the pointer and keys while zoomed out. Everything below
follows from that, and from Hyprland's function hooks working only on x86_64: Expanse uses none,
so it runs on ARM and x86 alike.

- **Camera.** A camera (origin + scale) maps the canvas to the monitor. Canvas coordinates are the windows' real positions, so at 100% the camera changes nothing and Hyprland draws everything itself.
- **A layout of its own.** Expanse registers a Hyprland layout, `expanse`, and a workspace with that layout is a canvas; every other workspace keeps its own layout and Expanse leaves it alone. The layout tiles nothing: a window handed to it to tile floats where it is (Hyprland hands a workspace's windows to a new layout one at a time, tiling the rest again in the old one as each leaves, so where each one was is noted as the layout is made).
- **At 100%, windows are real.** Every window on a canvas workspace floats where the canvas puts it, off-screen included. Input, focus, popups and X11 apps all stay native.
- **Zoomed out, windows are drawn through the camera.** No function hooks: Hyprland's only work on x86_64. At the start of each frame the plugin hides the canvas windows from Hyprland's own pass. After Hyprland's windows, it draws each one where the camera puts it, by giving it that box as its current (animated) geometry until the frame is drawn, the way Hyprland draws a window mid-animation, then restores it. Underneath is the desktop picture as it is, as on the Mac (or a plain background, in the theme's light or dark); the bar stays on top. A window closed on the canvas just goes, rather than fading out at its real size. Pointer and keys go to the canvas, not to apps.
- **On the canvas, windows are arranged for real.** Dragging, snapping and tidying move the real windows (still drawn through the camera), so there's nothing to reconcile when you leave. The snapping, tidy-up and placement rules are Expanse's, ported line for line.
- **Drawn as Expanse draws them.** Zoomed out, every window has Expanse's soft shadow, in canvas units so it shrinks with the window, and (with Window Names on: off, as on the Mac) its name just above it. Hyprland lays its decorations out for a window's real box, so the windows are drawn without them and each gets its theme border, in its colours, where the camera puts it; during a glide too.
- **Frames.** Hyprland draws a monitor only when something on it has changed. While the camera moves (a glide, a zoom, a pan coasting), each frame asks for the next while it's being drawn, so motion runs at the display's refresh rate; asked for any earlier, Hyprland drops the request. Text is never made mid-motion: a texture made while a frame is on the GPU waits for that frame to finish. Window names are made ahead, a few at a time while nothing moves (as windows open, and after the canvas closes), and kept while they fit; while the camera moves a name keeps the text it has (cropped to its window). The zoom under the minimap is set from digits made once. Only windows on the monitor are drawn.
- **Gliding** animates the camera (geometric zoom, straight-line pan of the view's centre), then moves every real window once so the camera is back at 100%, and focuses the picked window. A hop at 100% is the same glide without the zoom: for 0.3 s every window is drawn through the camera.

## In detail

At 100%, clicking a window that isn't fully on screen centres it, unless you were already working in it, or you've put the view where you want it yourself (scrolled or panned at 100%): then a window you can see, even partly, gets focus where it is, clicked or dived into, until the next glide, zoom or screen change; typing as it glides goes on into it, as on the Mac. A two-finger pan on a touchpad coasts on after your fingers lift. A scroll at 100% snaps when it stops (its coasting done, the fingers lifted with none to follow, or a wheel paused for a quarter of a second): the view moves by the least that leaves at least one window whole and the fewest cut off by the screen's edges, lining window edges up a gap in from the screen's, at most half a screen. On the canvas the pointer is an arrow, an open hand while <kbd>Space</kbd> is held and a closed one while panning. Diving into a window, the canvas stays drawn (names, minimap) until you're there; a click, scroll or pinch meanwhile stops it, still on the canvas. Toggles (auto-centre, pause) say so in a short message near the bottom of the screen.

The canvas is remembered in `~/.local/state/expanse/layout.json` (window titles only as a hash): reloading the plugin brings it back exactly, and a window an app opens again, after a restart too, returns to its spot. Unloading the plugin puts every window back where it was before the canvas, tiled ones back into their workspace's layout (the layout is saved first, while the workspaces are still Expanse's). Pausing does the same, except that a workspace still in Expanse would float a tiled window again, so there one that arrived tiled goes back to the box it had when it arrived; resuming brings the canvas back.

A workspace that takes another layout leaves the canvas: windows that arrived tiled tile again, and the rest stay where they are if they're on screen, or go back to where Hyprland had them (the middle of the screen, if that's off it too). Back in Expanse, every window goes back to its spot on the canvas, with the canvas's scroll, as if it had never left (kept while the plugin is loaded); a window opened meanwhile floats where it is. Omarchy's floating mode is handled in place both ways: going to it, Expanse hands Omarchy the windows that arrived tiled (with Omarchy's tag, so Omarchy tiles them when its mode ends), and coming from it, Expanse takes Omarchy's over. On Omarchy, <kbd>Super</kbd> + <kbd>L</kbd> cycles a workspace through tiling, scrolling, floating and Expanse ([omarchy/expanse](../omarchy/expanse) `layout`, in Omarchy's own mode files, notification and bar), and "every workspace" makes Expanse Omarchy's default layout, switching the workspaces there are now as well; turning it off brings the default from before back.

**Tidy Up** (<kbd>T</kbd> zoomed out, or the menu) tidies each group of windows where it is: overlaps pushed apart, edges within 60 px of lining up lined up, gaps closed to 20 px. A group only moves, as a whole, when another has grown into its space. **Restore Layout** puts this workspace's windows back where an earlier layout had them, fitted to this screen: a snapshot of the layout is kept when it has changed and the newest is 15 minutes old, the newest three of them, and the layout a restore replaces becomes one itself, so a restore can be undone (`hyprctl expanse layout` lists them, `layout 0` restores the newest).

The canvas follows you between screens: it keeps a home layout at the sizes you chose. On a smaller screen windows shrink to fit and the layout tightens: each window keeps its gap to its nearest window on the left (and above), or, nearer still, its offset from the window above or below it, so a column stays lined up and a window keeps with its own group. A screen change moves each window only as far as the change moves it in that derived layout, worked out from the two screen sizes rather than measured, so a round trip between two screens comes back exactly and a reload on the same screen moves nothing (the size each workspace was fitted to is kept with the layout). Windows opened or moved on a smaller screen, and any whose home spot doesn't explain where they are, get a home spot from their neighbours there, so they move along with them. Every fit keeps 16 px from the screen's edges. When a monitor changes size, the window you were in goes in the middle of it, as on the Mac (a workspace that lands on another monitor keeps its windows' places instead, see below), and a window too big for the screen shrinks to fit as you go to it. Apps that size in steps (a terminal to whole character cells) come within 32 px of the size asked for, and that counts as the size you chose. Windows of VMs and remote desktops (virt-manager, GNOME Boxes, VirtualBox, VMware, QEMU, Remmina, Moonlight, FreeRDP, VNC viewers and the like) size themselves to match the screen they show, and are never resized.

Every workspace in Expanse has a canvas of its own. As on the Mac, the minimap and the workspaces bar are on the desktop at 100% too, under your windows, and a click on a tile there goes to that workspace. Zoomed out, the workspaces bar beside the minimap (Expanse's Spaces bar) shows each workspace on the monitor as its desktop picture with a small map of its windows around it, the one you're on outlined; it's hidden while there's only one. Tiles are named as Omarchy's bar names them: with its workspaces 1-10 per monitor, 47 on the fifth monitor is "Workspace 7", the one <kbd>Super</kbd> + <kbd>7</kbd> goes to there. Going to another workspace with the canvas up, from the bar or a workspace bind like <kbd>Super</kbd> + <kbd>2</kbd>, brings the canvas along, zoomed out, so you can pick a window there; the one you left settles where leaving it would have taken you.

New windows open beside the window they came from (the app's front window in view, else the window in front), instead of on top of it: every spot along its edges is tried, right, below, left, then above, before anywhere further out; if that spot is off screen, the canvas glides there. Several opening at once get one glide, to the one in focus among them (else the newest), once they've all arrived. A new tab in a group (Hyprland's tabbed windows) stays in the group's spot. A window back from last time goes back to its spot: an app's first window, or several opening together (a browser bringing its session back), since apps here seldom reopen their windows themselves; a window opened while others of its app are open is new, so a second terminal opens beside the first, not where an old one was. A window opened on a workspace that isn't showing gets free space on that workspace's canvas; one that opens mid-glide, or elsewhere while you're zoomed out, is placed once the canvas is back at 100%. Dialogs keep the spot their app gives them. An open menu isn't drawn on the canvas (on the Mac it closes as the canvas takes the keyboard); back at 100% it's still there.

With several monitors, each shows its workspace's canvas, with its own minimap and workspaces bar, and zooms out on its own. A canvas reaches past its monitor's edges, over its neighbours', but a window parked there is neither drawn on the neighbour nor clickable there; keyboard focus still reaches it and centres it on its own monitor. Each workspace remembers the screen it was laid out for, so following you between screens works per monitor, and a workspace that moves to another monitor (when one is unplugged, say) keeps its windows where they were on the screen. A bar arriving or going (Omarchy's, hidden with <kbd>Super</kbd> + <kbd>Shift</kbd> + <kbd>Space</kbd>, or one that appears a moment after a monitor is plugged in) moves the windows with the space below it, without counting as a resize: nothing is recentred. Nothing tells a plugin when a bar takes space, so the canvas checks before each frame. Workspaces Hyprland or Omarchy renames as monitors come and go (Omarchy renumbers a monitor's workspaces into its block) keep their canvas, while the plugin is loaded and across a reload. Expanse on the Mac manages one display.

Zoomed out (or after scrolling on the desktop), keys go to the canvas. <kbd>Super</kbd> stands in for the Mac's <kbd>⌘</kbd> and <kbd>Ctrl</kbd>, so <kbd>Super</kbd> + <kbd>W</kbd> on the canvas closes the hovered window instead of the focused one.

The nearest window that way is the one Expanse on the Mac picks: a window sharing the row (or column) wins, nearest first; failing that, the closest within ~35° of straight that way. A hop pressed mid-glide hops on from the window the glide is heading to.

<kbd>Super</kbd> + arrows take over from Omarchy's focus keys (Hyprland's `movefocus`), which do the same job on a canvas less well: they pick by angle between centres, never centre the window, and can't chain. Hyprland fires every bind on a key, so the example config unbinds those four first, and on a workspace in another layout (or with Expanse paused) they do what `movefocus` did. With auto-centre off, a hop to a window that's already on screen focuses it where it is. Like `movefocus`, a hop lands with the pointer on the window (unless `cursor:no_warps`), so focus that follows the mouse stays put; a click-centre leaves the pointer where you clicked. <kbd>Ctrl</kbd> + arrows stay with apps for word-jump.

Focus moved from the keyboard (Alt-Tab, other binds) also centres a window that isn't fully on screen, once focus settles: it often bounces between windows for a moment, so as on the Mac the canvas goes where it lands 120 ms later. With auto-centre off the canvas stays put, and for a window all but off screen a message says where it went. Focus that follows the mouse never moves the canvas.

As on the Mac, the canvas never covers another app's dialog. A window pinned above the rest (picture in picture, Omarchy's webcam overlay) stays above the canvas while you're zoomed out, at its own size, and takes its own clicks. A dialog, a password prompt (polkit's, pinentry's, the keyring's) or a pinned window that opens while you're zoomed out brings you back to it, at 100%; one that opens during a glide, once the glide lands. It gets the keyboard, which the canvas otherwise keeps while you're zoomed out.

A full-screen (or maximised) window sits outside the canvas, as a full-screen app does on the Mac: zooming out takes it out of full screen, back to its spot among the others. Leave without picking a window, or pick it, and it goes back to full screen; pick another and it stays where it is on the canvas. A window coming back from full screen gets the view, wherever it was on the canvas.

## Next to the Mac

- **Zoomed out, keys go to the canvas, not to apps**: they move the highlight, zoom and tidy. Click a window (or press <kbd>Return</kbd>) to use it.
- **One canvas per monitor.** Expanse on the Mac manages one display; here each monitor's workspace is a canvas of its own (see above).
- **Menus can't list snapshots by time.** On the Mac, Restore Layout lists each snapshot by when it was taken; Omarchy's menu rows are fixed, so they're Newest, Earlier and Earliest (each shown only when it exists), and `hyprctl expanse layout` gives the times.
- **Nothing to put back when a VM window resizes itself.** On the Mac a VM app moves its window to keep it centred as the guest's resolution changes, and Expanse puts it back; on Wayland an app can't move its window, and Hyprland keeps a floating window's spot.
- **No smart zoom.** A two-finger double-tap on the Mac's trackpad zooms out, or to 100% around the pointer; libinput has no such gesture.

## Scripting, debugging and tests

`hyprctl expanse` prints the canvas as JSON. `hyprctl expanse` with `toggle`, `open`, `close`, `tidy`, `centre` (the window you're in), `layout [<n>]` (lists the layout snapshots, or restores one, 0 the newest), `fit`, `zoom <scale>`, `pan <dx> <dy>`, `hop <left|right|up|down>`, `focus <app>` (or `focus address:0x…`, from `hyprctl clients`), `space <name>` (that workspace's canvas, zoomed out), `select all`, `restore` (every window back into view), `pause [toggle]`, `resume`, `autocentre <on|off|toggle>`, `wallpaper <on|off|toggle|default>`, `corner [<corner>|default]` (no corner prints the hot corner's state), `names <on|off|toggle|default>`, `log` (this run's log), `logging [on|off|toggle]` (Detailed Logging: every line to `~/.local/state/expanse/expanse.log` too, at most 5 MB, the older half kept as `expanse.1.log`) or `keys` (the canvas's keys) drives it, and `pick <x> <y>` clicks the canvas at a global logical point. For debugging, `screen <w> <h>` pretends the screen is that size (no size for the real one), and `pinch <scale>…` sends a two-finger pinch through Hyprland's own input path, as a touchpad would. `perf start` records every frame until `perf stop` prints them as JSON (when each started and reached the screen, how long it took to draw, how much of that was the plugin, and how much making text); `perf start gpu` also waits for the GPU to finish each one, to time that. The state's `glides` counts the glides since the plugin loaded, and `lastAnimation` says how the last animation went, as Expanse's log does on the Mac: when its first frame came, how many, and the longest gap. In Lua, `hl.plugin.expanse.pause()` toggles pausing and `restore()` brings windows back into view.

[scripts/sweep.py](scripts/sweep.py) goes through everything the README and this page say, in a Try Omarchy VM, and checks each from the plugin's state: 143 checks, on a headless monitor of its own ([scripts/sweep-monitors.lua](scripts/sweep-monitors.lua), so the VM's window can be moved or resized meanwhile), with real keyboard and pointer input through QMP, pinches and two-finger pans from a virtual touchpad ([scripts/touchpad.py](scripts/touchpad.py), through the kernel's uinput and libinput, as a real one; it needs root in the VM, given with `VM_ASKPASS`) and through Try Omarchy's own pinch device (the one the Mac's trackpad drives), more monitors (headless outputs), a dialog ([scripts/dialog.py](scripts/dialog.py)), the plugin unloaded mid-glide, zoomed out, mid-drag and as windows open, and the workspace switched to tiling and back with <kbd>Super</kbd> + <kbd>L</kbd>. It runs with Expanse as every workspace's layout (setup's "every workspace"), and puts the default back after. `make test` checks the nearest-window rule and the layout file case by case. The nearest-window rule, snapping, tidy-up (again for 0.1.20's group by group, on 4,000 layouts), free-space placement and the layout for a smaller screen (again for 0.1.22's: its anchors, home spots worked back from a smaller screen, and re-homing, on 26,000 layouts) were also checked against Expanse's own Swift on thousands of random layouts, with no differences.

[scripts/perf.py](scripts/perf.py) times each motion (zooming, panning, glides, hops, and Hyprland's own workspace switch to compare with) on Virtual-1, or with `headless` on a monitor of its own. Virtual-1 is only drawn as fast as the VM's window on the Mac shows it, so keep that window on screen while timing it.

[scripts/vm.sh](scripts/vm.sh) syncs, builds and reloads the plugin in a Try Omarchy VM over SSH. [scripts/qmp-input.py](scripts/qmp-input.py) presses keys and moves and clicks the VM's real pointer through QEMU's QMP socket; a virtual keyboard (`wtype`) can't trigger Hyprland keybinds. `hyprctl output create headless` adds a second monitor to test with (the QMP pointer reaches it), and `hyprctl output remove` unplugs it.
